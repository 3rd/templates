# rs-gui-tauri

Desktop application template built with Tauri v2: a Rust backend, a React and Vite frontend, and
a `#[tauri::command]` showing the IPC seam.

## Setup

```sh
nix develop
```

The dev shell provides the Rust toolchain, the `cargo tauri` CLI, Node.js, `pkg-config`, and the
GTK, WebKitGTK, and libsoup libraries `wry` needs.

Entering the shell first is optional. Run any `make` target from a plain shell and it re-enters
the dev shell on its own. Nix is the only thing that has to be installed, and the template does
not have to live in a git repository.

## Commands

```sh
make help
make dev      # vite dev server plus the app, with frontend hot reload
make run      # release build, run directly
make build    # release build, no bundling
make test     # cargo test
make lint     # cargo clippy with warnings denied, then tsc
make fmt      # cargo fmt
make clean    # cargo clean and remove dist, node_modules, src-tauri/gen
make verify   # lint, test, build
```

`make build` runs `cargo tauri build --no-bundle`, which builds the frontend through the
`beforeBuildCommand` in `tauri.conf.json`, embeds it, and links the binary. Drop `--no-bundle`
to produce installers. `bundle.icon` already points at the 32x32 placeholder
`src-tauri/icons/icon.png`; replace it with a full icon set, for example with
`cargo tauri icon`, before shipping installers.

The targets that need the frontend depend on a `node_modules` file target that runs `npm ci`,
so dependencies are installed once and only reinstalled when `package.json` or
`package-lock.json` changes. `npm ci` installs exactly what the lockfile pins and never
rewrites it.

## Structure

- `src/App.tsx` holds the starter shell (tabs, counter, note, settings) and the button that invokes the Rust `greet` command.
- `src/styles.css` is the shared desktop-shell layout.
- `src/main.tsx` mounts React.
- `src-tauri/src/lib.rs` defines the `greet` command and builds the Tauri application.
- `src-tauri/src/main.rs` is the binary entry point and calls into the library.
- `src-tauri/tauri.conf.json` sets the product name, window title and size, and the frontend
  build commands.
- `src-tauri/capabilities/default.json` grants the main window the core permission set.
- `flake.nix` defines the dev shell.

## Notes

- Rename points: `name` in `package.json`, `name` in `src-tauri/Cargo.toml` and the matching
  `lib.name` and the `rs_gui_tauri_lib` reference in `src-tauri/src/main.rs`, `productName` and
  `identifier` and the window `title` in `tauri.conf.json`, the heading in `src/App.tsx`, the
  `<title>` in `index.html`, the title of this README, and the `description` in `flake.nix`.
- The library and binary split follows the Tauri v2 layout, which is what the mobile targets
  require. Desktop-only projects can collapse it into `main.rs`.
- `LD_LIBRARY_PATH` in `flake.nix` is required, not decorative. WebKitGTK launches a separate
  web process and loads its GL stack at run time, so link-time paths alone are not enough.
- On Linux the app needs WebKitGTK 4.1 at run time. On macOS and Windows the system webview is
  used instead.
- `src-tauri/gen` is generated by `tauri-build` on every build and is ignored, not committed.
