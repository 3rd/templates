# go-gui-wails

A desktop application template built on Wails v2, which embeds a React frontend in the
platform webview and binds Go methods so the frontend can call them like async functions.

## Setup

```bash
nix develop
```

The dev shell carries the Go toolchain, Node, the Wails CLI, and GTK 3 with WebKitGTK, so
nothing has to be installed on the host.

Entering the shell first is optional. Run `make build` from a plain shell and the Makefile
re-enters `nix develop` for you, so nix is the only thing you need installed. Until git tracks
`flake.nix` and `flake.lock`, it addresses the flake as `path:`, so the template does not have to
live in a git repository either. Once both are tracked, nix copies only the files git knows about,
which keeps ignored build output such as `bin/` out of the nix store.

## Commands

Run `make help` for the list. The targets are `dev`, `run`, `build`, `frontend`, `bindings`,
`test`, `lint`, `fmt`, `clean` and `verify`.

`build` builds the frontend into `frontend/dist` and then links the Go binary into
`bin/go-gui-wails` with the frontend embedded. `dev` runs `wails dev`, which serves the
frontend from Vite with hot reload. `bindings` regenerates `frontend/wailsjs` after the bound
Go methods change. `test` runs the Go tests and typechecks the frontend, and `verify` runs
lint, test and build together.

## Structure

`main.go` embeds `frontend/dist`, opens a resizable window and binds `&Greeter{}`.
`greeter.go` holds the one bound method; every exported method on a bound struct becomes a
generated TypeScript function under `frontend/wailsjs/go/main`, which is checked in and
regenerated by `make bindings`.

`frontend/src/App.tsx` owns the starter shell in React `useState` and calls the generated `Greet`
from the Home tab, so both halves of the seam are exercised. `frontend/dist` keeps a
`.gitkeep` because `//go:embed all:frontend/dist` fails when the directory is missing. Vite
empties `frontend/dist` on every build and copies the file back from `frontend/public`.

## Notes

This template pins Wails v2.15.0 rather than v3. As of 2026-09 the newest v3 release is
`v3.0.0-beta.20`, still beta and still changing its API between betas; v2 is the released line
and the one the CLI in nixpkgs tracks.

nixpkgs has removed `webkitgtk_4_0`, so the app must build against the 4.1 ABI. Wails v2
selects it with the `webkit2_41` build tag, which the `Makefile` passes to every Go command
that compiles the webview, including `go vet` and `go test`. The tags `desktop` and
`production` are the ones the Wails CLI uses for its own release builds; the `Makefile` applies
them directly so the output lands in `bin/` instead of the CLI's `build/bin/`.

Watch out for a bare `go build .` in the dev shell: it succeeds, because the desktop frontend
sits behind the `desktop` tag and is simply left out, so the binary opens no window. Add
`desktop` and it fails loudly with `No package 'webkit2gtk-4.0' found` until `webkit2_41` is
added too. Use the `Makefile` targets rather than raw `go` commands.

The frontend uses npm rather than bun. Bun 1.3.13 crashes parsing the `@types/react` registry
manifest, so it cannot install this dependency set at all.

Building is verified on Linux only. The macOS shell drops GTK and WebKitGTK because Wails uses
WKWebView there, but that path has not been built.

To rename the template, change the module path in `go.mod`, the `appName` constant in
`main.go`, `APP` in the `Makefile`, `name` and `outputfilename` in `wails.json`, `name` in
`frontend/package.json`, the `<title>` in `frontend/index.html`, `appName` in
`frontend/src/App.tsx`, and the flake description.
